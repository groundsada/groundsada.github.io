This Site Runs on a Bash Web Framework

Yes, really: the site you're reading was built with bash-stack — an HTTP server and web framework written entirely in Bash. It's the kind of thing you build because it's fun and because it forces you to think about what a web framework actually needs. This post explains how it works, and what I fixed to make the blog functional.

How it works

  • File-based routing. Every route is a `.sh` file in `pages/` — `pages/index.sh` is `/`, `pages/blog.sh` is `/blog`, and `pages/blog/[slug].sh` renders individual posts. bash-stack's core (`core.sh`) parses HTTP requests in pure Bash and executes the matching page script.
  • Components. Shared bits — header, footer, intro, recent posts, projects — live in `components/` and are `source`d by the pages.
  • Markdown posts. Each blog post is a markdown file in `blog/` with YAML-ish frontmatter (`title`, `date`, `excerpt`). The page script pulls the frontmatter with `awk` and converts the body to HTML with `sed`. It's a miniature markdown engine, and it's about fifty lines.
  • Static output. A real site needs to survive GitHub Pages, so `build.sh` starts the server locally, `curl`s each route into `dist/`, copies the assets, and touches `.nojekyll`. The GitHub Actions workflow in `.github/workflows/deploy.yml` does the same thing on every push to `main` — install `ucspi-tcp` (for `tcpserver`), run the build, publish `dist/` to the `gh-pages` branch.

    • The bug that had to be fixed

    The original build only pre-rendered two pages: `/` and `/blog`. Every post link pointed at `/blog/` — but no post page was ever generated, so every individual blog post 404'd. Classic. The fix was small: have `build.sh` discover the markdown files and pre-render each one into `dist/blog/.html`. There's also a date-sorting fix in the "recent posts" component so the list actually orders newest-first and shows real dates.

    Why bash?

    Honestly? Because it's a fun constraint — and because a framework that can't afford to be complex is a nice reminder that most of "web development" is convention, not machinery. The components, the frontmatter, the static export: it all maps 1:1 to what Jekyll or Hugo does, just with fewer moving parts.

    The framework is [cgsdev0/bash-stack](https://github.com/cgsdev0/bash-stack) — give it a try if you like seeing how far shell can go.

    Built with bash-stack

    This site is powered by bash-stack, an innovative HTTP server and framework for building modern web applications entirely in Bash.

    Key Features:

    • File-based routing: All routes exist as .sh files in the pages/ folder
    • HTTP request handling: Framework locates and executes corresponding scripts
    • stdout to HTTP: Anything written to stdout becomes the HTTP response body
    • HTMX integration: Included by default for dynamic interactions
    • Static site generation: Pre-renders dynamic content for deployment

    Deployment & CI/CD

    This site is automatically deployed using GitHub Actions with the following workflow:

    Build Process:

    1. Trigger: Push to main/master branch
    2. Environment: Ubuntu runner with Node.js 18
    3. Dependencies: Install jq for JSON processing
    4. Build: Run build.sh to generate static files
    5. Deploy: Push to gh-pages branch via GitHub Pages

    Technical Stack:

    • Server: bash-stack (Bash 5+ with associative arrays)
    • Styling: Custom CSS (inspired by Basically Basic Jekyll theme)
    • Content: Markdown blog posts with frontmatter parsing
    • Data: JSON configuration files + GitHub API integration
    • Hosting: GitHub Pages (static site hosting)

    Architecture

    The site uses a component-based architecture where each UI element is a reusable Bash script:

    Components:

    • header.sh - Navigation and site branding
    • intro.sh - Profile section with social links
    • recent-posts.sh - Blog post listings
    • projects.sh - GitHub repository integration
    • footer.sh - This technical documentation

    Pages:

    • index.sh - Homepage composition
    • blog.sh - Blog listing page
    • blog/[slug].sh - Dynamic blog post rendering
